# Proof — Xray CSV export (issue #35), generated from US-004

`US-004-xray-import.csv` is a real export produced by applying the mapping rules in
`plugins/qaia-core/skills/generate/connectors/xray.md` to the actual US-004 test book
(`examples/expense-demo/qaia-journey/testbooks/US-004/*.feature` + `coverage-matrix.md`). Nothing in
this file is hand-written or fabricated — it was generated by parsing the real `.feature` files.

## How it was built and checked

A one-off Python script (decision D42 — session-generated, jettable, not shipped code) parsed the 4
`.feature` files, applied the connector's mapping table (Background flattening, `#` comments moved to
`Description`, tag → `Labels`/`Priority`), wrote the CSV with Python's `csv` module (RFC 4180
quoting), then **re-parsed its own output** and asserted:

- header row matches the 8 documented columns exactly;
- 38 rows (matches `synthesis.md`'s stated scenario count exactly — 1 smoke journey + 37 conditions);
- 38 distinct `QAIA-US-004-nnn` labels, no duplicates, no scenario missing one;
- every `Cucumber Scenario` field starts with a valid `Scenario:` line and contains no leaked `#`
  comment (comments were relocated to `Description`, not dropped or left in place);
- `Test Type` is `Automated[Cucumber]` and `Priority` is one of `Highest`/`Medium`/`Low` on every row;
- the `Priority` distribution came out **19 Highest / 15 Medium / 4 Low** — an exact match to
  `synthesis.md`'s independently-written "Priority split: 19 P1 / 15 P2 / 4 P3", a cross-check that
  the export didn't silently drop or reprioritize any scenario;
- the file round-trips as valid UTF-8 (checked at the byte level, not just via a terminal that may
  mis-render non-ASCII characters like the em dashes in the rationale text).

## What this does and does not prove

**Proves**: the connector's mapping rules are mechanically applicable to a real, previously-generated
QAIA test book, and the resulting CSV is syntactically well-formed per the documented schema.

**Does not prove**: that Jira/Xray actually accepts this file through its import wizard. No live Xray
instance was available in this session — see the honesty section of `connectors/xray.md` for the
exact caveats (Test Type literal may vary by Xray version, Labels multi-value mapping depends on the
wizard). Treat this as "well-formed per our own reading of Xray's docs," not "verified against Xray
itself."
